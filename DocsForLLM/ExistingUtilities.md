# Existing utilities and reusable patterns

Use this catalogue **before writing another helper, service, cache, formatter, or client wrapper**. It indexes checked-out source reviewed on 2026-10-23; inspect current definitions and callers before relying on a contract. This is not an exhaustive API reference or proof of runtime correctness.

Read [CodingStandards.md](CodingStandards.md) and [RepositoryGuide.md](RepositoryGuide.md) for coding and safety rules. Describing an API here is not permission to execute it: many constructors/services perform disk, network, database, or browser work. **Validation remains build-only.**

## Reuse workflow

1. Look up the responsibility below, then search related terms in source, including `Services/`, command bases, controllers, models, and image generation, not just directories named Utility.
2. Read the implementation and a caller. Check namespace/imports, public versus internal/file visibility, project references, required acknowledgement, state/lifetime, null/exception behavior, and resource ownership.
3. Reuse the helper/service if its semantics fit. Ordinary BCL/package operations need no extra abstraction; existing packages include Discord.Net, SmartFormat, CsvHelper, EF Core, PhigrosLibraryCSharp, PhiInfo, and PuppeteerSharp.
4. If it does not fit, explain the concrete gap. Extend an existing family only when appropriate; otherwise use a local helper or add a focused shared API at the lowest suitable layer. Do not force a flawed/incompatible helper, add a dependency to duplicate supported behavior, or expose an internal API merely for convenience.

### Localization lookup and mutation

Decision record: [ADR 0016](ADR/0016-LocalizationFallbackSimplification.md).

- **Lookup:** requested language, then its per-language chain (`LocalizationManager.LanguageSpecificFallback`) or the default chain (`CommonLanguageFallback`) if it has none, then the key name. Chains are explicit (no implicit continuation to the default chain; a chain without `en-US` falls to the key name) and configured globally on the manager in `Localization.json`; strings have no fallbacks of their own. Never reintroduce per-string fallbacks. A string with no manager resolves against an en-US-only chain. `LocalizedString.Default` (base command/option name and option-lookup identifier) is en-US first, then the default chain, then the key name, independent of per-language chains. The "then the key name" step applies only when a key name is set: a detached string with none (from `CreateDefault`, `CloneDetached`, `LocalizedString.Create`) throws `KeyNotFoundException` when no language in its chain has text.
- **Missing keys:** the manager indexer never throws; it returns a new detached string holding only the key name. `TryGet(key, out str)` is the non-defaulting lookup. Core `LocalizationService` logs a warning on every missing-key access and adds nothing to `Data`; keep the deployed file complete (`--addNonExistentLocalizations`).
- **Manager API:** `Strings` (read-only dictionary; the manager is not an `IDictionary`), `Add`/`Replace` (throw if the string already has a key or manager reference; `Replace` detaches the old one), `Remove` (detaches and returns it, `null` if absent), `DeepClone` (same chains, detached copy of each string re-added).
- **Clone helpers on `LocalizedString`:** `CloneDetached()` copies texts into a new dictionary with no key or manager reference, so it can be added to a manager. `MakePreFormatted(...)` builds formatted texts but keeps the key and manager reference (chain still applies), so the add guard rejects it; the copy keeps pointing at the manager it came from, so after a clone-edit-swap it still uses the old manager's chains. `LocalizedString.DeepClone` and `CloneAsNew` no longer exist.
- **Discord:** Discord localizations contain only a string's own translations; Discord shows the base text elsewhere and the chain does not apply.
- **Runtime changes:** the manager is shared by all commands. Clone `LocalizationService.Data` (`DeepClone`), edit the clone, then swap it in (as `LocalizationTool`'s `CsvToLocalization` does); never edit in place while commands run.

### Non-shared helpers are not hidden public APIs

Some useful-looking extensions are deliberately `file`-scoped or internal:

- `ImageGenerator.cs`: `AsFullPath`.
- `CollectionCommand.cs`: language-option helpers.
- `DownloadAssetCommand.cs`: `CopyToEntry`.
- `LeaderboardCommand.cs`: difficulty/status filtering extensions.
- `ReadOnlyDictionaryWrapper*.cs`: null-to-NotSupported guard.
- Framework `Utils.cs`: file-copy, console, and task-completion helpers.

`file` helpers are visible only within their defining file; `internal` helpers stay within their assembly. Adding a `using` cannot widen either boundary. If another caller genuinely needs the same behavior, inspect the existing implementation and decide whether a focused extraction belongs in the request. Otherwise use the appropriate BCL operation/local helper; do not copy entire implementations or silently widen access.

Plugin-local services/helpers may be the right reference for plugin-only behavior: for example `AdminHelper/Services/` requesters for statistics/reports and `MaintenanceNotificationService` (owns the nullable maintenance-notification channel, resolved by `ResolveChannelAsync` after initialization; inject it rather than resolving the plugin), `PersonalWebsite/Services/BlogManagerService.cs`, and `PhigrosLoginHost/HttpClientService.cs`. Their dependencies, auth checks, serialization, and side effects are not automatically general Core/Framework conventions.
