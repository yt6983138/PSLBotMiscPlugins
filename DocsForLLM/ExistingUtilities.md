# Existing utilities and reusable patterns

Use this catalogue **before writing another helper, service, cache, formatter, or client wrapper**. It indexes checked-out source reviewed on 2026-10-23; inspect current definitions and callers before relying on a contract. This is not an exhaustive API reference or proof of runtime correctness.

Read [CodingStandards.md](CodingStandards.md) and [RepositoryGuide.md](RepositoryGuide.md) for coding and safety rules. Describing an API here is not permission to execute it: many constructors/services perform disk, network, database, or browser work. What may be run is limited by [AGENTS.md](../AGENTS.md#required-policy).

## Reuse workflow

1. Look up the responsibility below, then search related terms in source, including `Services/`, command bases, controllers, models, and image generation, not just directories named Utility.
2. Read the implementation and a caller. Check namespace/imports, public versus internal/file visibility, project references, required acknowledgement, state/lifetime, null/exception behavior, and resource ownership.
3. Reuse the helper/service if its semantics fit. Ordinary BCL/package operations need no extra abstraction; existing packages include Discord.Net, SmartFormat, CsvHelper, EF Core, PhigrosLibraryCSharp, PhiInfo, and PuppeteerSharp.
4. If it does not fit, explain the concrete gap. Extend an existing family only when appropriate; otherwise use a local helper or add a focused shared API at the lowest suitable layer. Do not force a flawed/incompatible helper, add a dependency to duplicate supported behavior, or expose an internal API merely for convenience.

| [AliasService.cs](../PSLDiscordBotBase/PSLDiscordBot.Core/Services/AliasService.cs) | `SearchSong` (the `List` overloads are strict mode and sort with `CandidateSearch.CompareStrict`, so equal scores are deterministic; the table overload scores the single merged alias dictionary (`GetAliasesMerged`), so there are no ordered sources and a tie goes to key/name match, then song id ordinal ([user-facing tie order](../PSLDiscordBotBase/Documentation/AliasSystem.md#which-song-wins-when-several-match-equally)); the span overload used by autocomplete builds no merged dictionaries and ranks earlier sources first; for top-N partial search call `CandidateSearch.Search` with `info.Songs` and key/name selectors), merged/inherited aliases, cached table access (`GetCachedAliases` returns the per-table immutable snapshot without copying; treat it as read-only and re-fetch to see later mutations), static/dynamic requesters, `MutateAliases`, metadata mutation. | Interaction overload selects server/global scope; search returns ranked matches. Matching lives in the static, pure `CandidateSearch` (`Core/Searching/`, namespace `PSLDiscordBot.Core.Searching`, no DI/database; callable from tests): `SearchHit<T>` (`Item`, `Key`, `Name`, score, matched text, `AliasSource`: -1 if the matched text is the key or name (key/name wins ties, so also when it ties an alias), otherwise the index of the alias source in the alias span; `FromAlias` is derived, `AliasSource >= 0`); `Search<T>` / `SearchAll<T>` take the source `IEnumerable<T>` plus static `Func<T, string>` key and name selectors and an ordered `ReadOnlySpan` of alias dictionaries (keyed by item key; pass a collection expression such as `[aliases]`, which does not allocate). Sources are scored in the given order with a strictly-greater rule, so on a tie the key, then the name, then the earlier source labels the hit (`AutocompleteSuggestionService` passes server before global). They lowercase with `ToLowerInvariant` while scoring (no candidate objects, no caches); `CandidateSearch.Normalize(string)` is that normalization, use it for any case-insensitive check that must agree with search; `CandidateSearch.CompareStrict<T>` is the total order for strict results (score descending, then `AliasSource` with key/name first, then key ordinal); `Search` fills a span with the top hits by insertion and returns the count, `SearchAll` collects every match unsorted in source order; both take `double threshold, bool allowPartial` (`threshold` is the minimum fuzzy Levenshtein ratio in both modes; `CandidateSearch.DefaultThreshold` = 0.75 is the default for search thresholds). Strict mode is the command scoring with both sides lowercased. Its spec (tested) is: a case-insensitive exact match scores 1 and always passes, `threshold` is the minimum score, fragments and clearly different input do not match, near misses do. The half-length gate, the Levenshtein ratio and scores other than 1 are tunable implementation details. Partial mode (`allowPartial: true`, used by `AutocompleteSuggestionService` with its `FuzzyThreshold`) ranks exact > prefix > substring > fuzzy (ratio `>= threshold`) by `CandidateSearch.Tier*` constants and returns nothing for empty or whitespace-only input. Threshold 0 makes strict mode match everything. Table ids are the closed `AliasTableId` struct (`Services/AliasTableId.cs`; no public constructor, `default` is `Global`): factories `Global`, `Avatar`, `Server(guildId)`, `ForInteraction`; strict `TryParse` (exact kind name, decimal digits only, leading zeros accepted and normalized, Global/Avatar only id 0); `Kind` (`AliasTableKind`), `Id`, `IsGlobal`/`IsServer`/`IsAvatar`, and the rules `DefaultParent`, `AllowsInheritanceByDefault`, `KeysAreSongIds`. `ToString()` is `Kind_Id`, the SQLite table name and the stored `TableId`/`InheritsFrom` text, so never change it; strings exist only at that persistence boundary, and an unparseable stored `InheritsFrom` ends the inheritance chain with a warning. `AliasTableId.Avatar` (table `Avatar_0`) is a hidden table keyed by avatar key instead of song id: `GetDefaultAttribute` gives it no parent and `AllowInheritance = false`, so servers cannot inherit from it; `GetDynamicTableRequesterAuto` supports only Server/Global and throws for other kinds (use `GetDynamicTableRequester(AliasTableId.Avatar)`). Song search methods must not be pointed at it. `AliasTableId.TryParse` parses `ToString()` output strictly (exact `Kind_number`, digits only, leading zeros normalized, Global/Avatar only with id 0; no database access) and must run before a requester is created from user-supplied table ids, because `GetDynamicTableRequester(AliasTableId)` creates the table it is given. `AliasService.TableExists` checks a table without creating it (loaded cache, then the SQLite schema); `GetExistingServerTables` lists the server tables present in the schema (creates nothing; used by the startup preload). The rules live in the pure static `AliasConflictCheck.Check<T>` (`Core/Searching/`, unit-tested): case-insensitive via `CandidateSearch.Normalize`, first hit in song order; `replacing` ignores only the single stored entry of the target that is ordinal-equal to it, and an ordinal-identical new alias is a no-op rejected as `DuplicateOnSameSong`. The rule order is described in [AliasSystem.md](../PSLDiscordBotBase/Documentation/AliasSystem.md#rules-for-adding-an-alias); rename behaviour is in its `audit modify` bullet under [Server Admin Commands](../PSLDiscordBotBase/Documentation/AliasSystem.md#server-admin-commands). There are no warnings. Used by the `add` leaves of `/alias-global` and `/alias-server` (`AliasGlobalCommand`, `AliasServerCommand`; shared reply mapping `AliasModifyHelper.ReplyIfRejected`, with `SearchAndValidate`, `SearchThreshold` and `SongSearchValidateResult` in `Command/Global/Aliases/AliasModifyHelper.cs`) and `/alias-server-admin audit modify`; `alias-admin` and `MigratorPlugin` are not validated. Requesters generally need explicit saves; some mutation methods save internally. Do not promise cross-context atomicity or write raw table IDs/aliases around these paths. |

### Non-shared helpers are not hidden public APIs

Some useful-looking extensions are deliberately `file`-scoped or internal:

- `ImageGenerator.cs`: `AsFullPath`.
- `CollectionCommand.cs`: language-option helpers.
- `SongCommand.Assets.cs`: `CopyToEntry`.
- `LeaderboardCommand.cs`: difficulty/status filtering extensions.
- `ReadOnlyDictionaryWrapper*.cs`: null-to-NotSupported guard.
- Framework `Utils.cs`: file-copy, console, and task-completion helpers.

`file` helpers are visible only within their defining file; `internal` helpers stay within their assembly. Adding a `using` cannot widen either boundary. If another caller genuinely needs the same behavior, inspect the existing implementation and decide whether a focused extraction belongs in the request. Otherwise use the appropriate BCL operation/local helper; do not copy entire implementations or silently widen access.

Plugin-local services/helpers may be the right reference for plugin-only behavior: for example `AdminHelper/Services/` requesters for statistics/reports and `MaintenanceNotificationService` (owns the nullable maintenance-notification channel, resolved by `ResolveChannelAsync` after initialization; inject it rather than resolving the plugin), `PersonalWebsite/Services/BlogManagerService.cs`, and `PhigrosLoginHost/HttpClientService.cs`. Their dependencies, auth checks, serialization, and side effects are not automatically general Core/Framework conventions.
